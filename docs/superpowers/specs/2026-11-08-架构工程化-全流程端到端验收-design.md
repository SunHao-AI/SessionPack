- 日期：2026-11-08

- 来源：Spec 5 N-1 决策"入口层薄壳 E2E 测试如需要再单开 spec"；
  Spec 7 §7 不做项"E2E-1 全链路应单开 spec，不夹带"

## 1. 背景与问题

前七个 spec 把分层、命名、渲染、配置、索引一致性全部收口，但测试
金字塔的顶层是缺的：

- 现有"闭环"都是碎片闭环：`test_acceptance.py` 归档往返+导出、
  `test_sync.py::TestRealRoundTrip` 双设备复制-校验-导入、
  `test_server.py::TestEndToEndHttp` 归档→serve。没有任何一条测试
  贯穿 **import → 检索 → 导出归档 → push → pull → rebuild → serve**。
- 全部测试走进程内调用（`run_xxx(args)` 直接返回 `CommandResult`），
  从没经过真实入口：`python -m sessionpack` 薄壳、argparse 参数表、
  stdout/stderr 落盘、退出码传导——这些环节坏了现在没人知道。

索引库是纯派生缓存、归档包是唯一跨设备载体的架构，其最大风险恰恰是
"每个模块各自正确、串起来不对"。本 spec 补这层回归保险。

## 2. 目标与非目标

目标：

- **E2E-1 全链路**：一条测试贯穿双设备全流程（见 §4），任何一环断裂
  当场暴露。
- **E2E-2 CLI 子进程冒烟**：真实 `python -m sessionpack` 子进程验证
  入口薄壳、参数表、编码、退出码（见 §5）。

非目标：

- 性能/并发测试（多进程同时 push/pull 的竞态）——另议。
- 真实网络或 WebDAV——同步载体仅本地目录，不扩面。
- 浏览器端 Web UI 行为——serve 只断言 HTTP API。
- 不新增任何生产代码。本 spec 是纯测试增项；若链路测试暴露生产 bug，
  按"发现即修"处理并记入落地记录。

## 3. 硬约束（沿袭 Spec 7 §3）

1. 每个 commit 前 `python scripts/check.py` 五步全绿。
2. 既有测试不删不改断言；267 → 275（+8）。
3. 零运行时第三方依赖（`subprocess`/`urllib`/`threading` 均为 stdlib）。
4. 不写 CI；`spike/` 不动；BASELINE 保持空集；E_SQL 白名单不扩大。
5. 门面 `__all__` 锁全等测试不动；新增公共名一律子模块直导。
6. 对话、注释、commit message 全中文。

## 4. E2E-1：全链路测试（tests/test_e2e_flow.py）

### 4.1 方案

复用 `conftest.memory_tree`（RepoA 2 条 + RepoB 2 条 + 1 行坏数据），
全程走 `run_xxx` + 目录级断言，双设备 = 两个独立 data_dir + 一个共享
sync_dir：

| 步骤 | 动作 | 断言 |
|------|------|------|
| 1 | A：`run_import` | 2 会话 4 消息，`rows_failed==1` |
| 2 | A：`catalog.search_messages("校验")` | 命中 RepoA 会话（检索环） |
| 3 | A：`run_export --archive --all` 落 `A/archives` | zip 落盘 |
| 4 | A：`run_push --dir sync` | pushed==1，sync 目录可见 |
| 5 | B：`run_pull --dir sync` | 包复制到 B/archives 并入库 |
| 6 | B：`search_messages("检索")` | 命中来自 A 的 RepoB 会话 |
| 7 | B：手删 1 条 message_fts 行 → `run_doctor --json` | `fts.drift is True`（FTS-1 环） |
| 8 | B：`run_rebuild --fts` | drift 归零，步骤 6 检索恢复 |
| 9 | B：`run_rebuild --from-archives --yes --json` | stats 与 A 一致，`.bak` 存在，无 `.staging` 残留（FTS-3 环） |
| 10 | B：`create_server(port=0)` 线程内起服务 | 见 4.2 serve 环 |

### 4.2 serve HTTP 环（独立测试）

沿用 `test_server.py` 既有手法（线程 + `port=0` + `urllib`），但数据源
是 E2E-1 同款"pull 而来"的 B 库：

- `GET /api/sessions?token=…` → 200，含 A 侧会话；
- `GET /api/sessions/<sid>?token=…` → 200，消息字段完整；
- 无 token → 403。

serve 环独立成测的原因：它需要起线程，与主链的纯函数断言分离，
失败时定位面更小。

### 4.3 验收

- 主链测试单条贯通 §4.1 全部 10 步；中途任何断言失败即红。
- 用后即弃：全部落在 `tmp_path`，无残留。
- 主链 + serve 环 = +2 测试。

## 5. E2E-2：CLI 子进程冒烟（tests/test_cli_smoke.py）

### 5.1 方案

统一助手 `_run(*argv, cwd=REPO_ROOT)`：
`subprocess.run([sys.executable, "-m", "sessionpack", *argv], …)`，
`cwd` 固定仓库根（`Path(__file__).resolve().parents[1]`），
env 注入 `PYTHONIOENCODING=utf-8`，捕获时显式 `encoding="utf-8"`。

### 5.2 用例（+6）

| 用例 | 断言 |
|------|------|
| `--help` | 退出码 0，stdout 含"可用命令" |
| 未知子命令 | 退出码 2，stderr 非空 |
| `import` 记忆目录不存在 | 退出码 2（EXIT_USAGE），stderr 含"记忆目录不存在" |
| import→doctor 冒烟 | 用 `conftest.write_jsonl` 铺最小记忆树，`--json` 输出可 `json.loads`，`stats` 键齐全 |
| export→verify 闭环 | `export --archive --all --out <data>/archives` 后 `verify --archives <zip>` 退出码 0 |
| rebuild --fts 冒烟 | `--json` 解析出 `rebuilt` 为 int，退出码 0 |

### 5.3 验收

- 每条断言真实进程的退出码 + 编码后的输出文本；
- 单条子进程测试超时上限 60s（`timeout=60`），超时必须失败而非挂死。

## 6. 风险与决策

1. **Windows 控制台编码**：子进程 stdout 重定向后默认 locale 编码
   （GBK），中文断言会乱码。对策：env `PYTHONIOENCODING=utf-8` +
   `subprocess.run(encoding="utf-8")` 双保险，写进 §5.1 助手，测试侧
   不再各自处理。
2. **入口可导入性**：子进程 `python -m sessionpack` 依赖 cwd 或
   PYTHONPATH 含仓库根。cwd 固定仓库根即可，不设 PYTHONPATH（少一个
   变量）。
3. **端口竞争**：serve 环 `port=0` 随机端口，与 `test_server.py` 现状
   一致。
4. **E2E-1 是"厚"测试**：单条测试串 10 步，失败时定位成本高。接受：
   全链路语义就是它的价值；步骤断言消息全部带步骤号，红行自解释。
5. 若 E2E 暴露生产 bug：本 spec 内最小修复 + 回归测试注记，写进落地
   记录；不为测试放宽任何生产断言。
