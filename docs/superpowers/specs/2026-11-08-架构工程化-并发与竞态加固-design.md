## 1. 背景与问题

本工具的设计前提是"单机、双设备、经同步目录交换"，但没有任何一处
禁止（也没有测试约束过）两个进程同时操作同一数据目录或同一同步目录。
立项探针在 Windows 上实测出两类真实缺陷、一类"已经安全"、一处顺带
发现：

| 编号 | 场景 | 实测结果 |
|------|------|----------|
| F1 | 两进程 push 同名包到同一同步目录 | **缺陷**：4 进程并发 push 退码 `[0,1,0,1]`，虚假失败 |
| F2 | 他进程持连接时 `rebuild --from-archives` | 失败模式优雅：`换入失败，已回滚，原索引未改动`，退 1，原库完好、无 staging 残留（但此不变量无回归测试锁定） |
| F2b | 三进程同时 `rebuild --from-archives` | **缺陷**：退码 `[1,0,1]` 且数据目录残留**两个 `.bak`**，其中一个是孤儿（库完好、stats 正常） |
| F3 | 四进程同时 import 同一库 | 安全：全部退 0，stats 精确收敛（2 会话/4 消息），重跑幂等不翻倍 |
| 顺带 | config.toml 并发写 | `save_last_sync_dir` 直接 `write_text` 非原子，撕裂写可毁掉 `[sync]` 配置 |

## 2. 根因（逐字对现场）

1. **F1**：`sync._atomic_copy` 的临时名固定为 `".tmp-" + dest.name`
   （[sync.py](../../../sessionpack/sync.py) L46），**不含写者标识**。两个
   写者推同名包时临时路径完全相同：互相覆盖半成品，`finally` 里
   `tmp.unlink(missing_ok=True)` 还会删掉对方的在途临时文件；Windows 上
   `os.replace` 撞上他进程正持有的临时文件句柄直接抛
   `PermissionError [WinError 32]`。
   注：同名包内容必相同（文件名尾 12 位是内容 sha256，
   `compute_archive_id`），所以损害限于**虚假失败与在途互踩**，
   不存在静默内容损坏（探针 4MB 重叠写实测目标内容恒为完整 A 或完整 B）。
2. **F2b**：换库序列"原库→`.bak`（先 `unlink` 旧备份）、staging→原库"
   无写者协调。两个重建进程交错时，输家的 `.bak` 成为孤儿；且赢家换入
   瞬间输家的 `_cleanup_sidecars_only` 会误删赢家的 `-wal`。
3. **F3 安全的原因（要保住，不许退化）**：`busy_timeout=5000` + 每文件
   一事务 + 全表 UPSERT 幂等。
4. **config**：`save_last_sync_dir` 直接覆写 `config.toml`，崩溃/撕裂
   留下半截 TOML，下次 push/pull 将报解析失败。

## 3. 目标与非目标

目标（全部最小修复，不引入守护进程与外部依赖）：

- **R1 push/pull 临时名写者唯一**：`.tmp-<目标名>.<pid>.<uuid4 前 8 位>`。
  必须保留 `.tmp-` 前缀——`_TEMP_PREFIXES` 的"临时文件不当真包"
  语义与既有测试（`test_sync.py` 的 `.tmp-*` 断言）依赖它。
  同名目标竞态的良性结局：`os.replace` 抛 `FileExistsError`
  （Windows 目标被占）时，push 视作"已存在"跳过、pull 视作"已由他人
  拉取"，不报错误。
- **R2 换库竞态收敛**：换入对 `PermissionError` 做有限重试
  （5 次 × 0.2s 退避，专治 Windows 共享冲突），重试尽仍失败则走既有
  回滚路径，文案不变；`.bak` 命名改为 `.bak-<UTC 时间戳>`，
  消除孤儿备份互相覆盖，孤儿 `.bak-*` 可被用户安全删除（文档一句）。
- **R3 config 原子写**：`save_last_sync_dir` 改"唯一临时名 + `os.replace`"，
  失败路径不留残file。
- **R4 回归测试**：把 F2 的优雅结局与 F3 的幂等收敛从"探针实测"升级为
  测试锁定；探针用过的三组竞态各有对应测试。

非目标：

- 进程间互斥锁/单实例锁（文件锁、`msvcrt.locking`）——重试 + 幂等已
  覆盖实测缺陷，锁带来的死锁/残留锁问题超出问题规模。
- 性能基准（另议，维持 Spec 8 决定）。
- WebDAV/网络盘的竞态（同步载体仅本地目录，与 Spec 8 一致）。
- 多线程（同进程）并发调用的支持承诺——只测多进程。

## 5. 设计

### 5.1 R1：sync._atomic_copy（sync.py）

```python
def _atomic_copy(src: Path, dest: Path) -> None:
    dest.parent.mkdir(parents=True, exist_ok=True)
    tmp = dest.parent / (f".tmp-{dest.name}.{os.getpid()}."
                         f"{uuid.uuid4().hex[:8]}")
    try:
        shutil.copy2(src, tmp)
        os.replace(tmp, dest)
    except FileExistsError:
        # Windows：目标正被他进程持有（同名包内容必相同），良性竞态
        pass
    finally:
        tmp.unlink(missing_ok=True)
```

调用侧语义核对：`push_archives`/`pull_archives` 现有 `except OSError`
收集错误的分支不动（真 IO 错误仍上报）；`FileExistsError` 在函数内
消化为"已由他人完成"，不计 errors。pull 侧 `if dest.exists(): 跳过`
的既有短路保持。

### 5.2 R2：换库重试与备份命名（rebuild.py）

- `os.replace(layout.catalog, bak)` 与 `os.replace(staging, layout.catalog)`
  各包一层 `_replace_with_retry(src, dst)`：捕 `PermissionError`，
  0.2s × 5 次退避重试，仍失败原样抛出走既有回滚。
- `bak` 改为 `catalog.sqlite.bak-20261108T123456Z`（UTC 紧凑时间戳）。
  `report.backup` 字段照常返回实际路径。README 索引维护小节补一句：
  旧格式 `catalog.sqlite.bak` 与 `bak-<时间戳>` 均可随时手删。
- 既有测试断言核对：D3 测试只断言 `.bak` 存在性/`backup` 字段（无精确
  文件名锁），改名安全（实施时逐字复核，若发现锁死断言则按
  "既有测试不改"精神调整方案而非改测试）。

### 5.3 R3：config 原子写（config.py）

`save_last_sync_dir` 落盘改：写 `config.toml.tmp-<pid>.<uuid 前 8>` →
`os.replace` → 失败路径 `unlink(missing_ok=True)`。返回 `None`/`str`
的既有契约不变（Spec 6 CFG-1 测试不动）。

### 5.4 R4：测试（tests/test_race_concurrency.py，+6）

| 用例 | 层 | 断言 |
|------|----|------|
| 重叠写同名目标（barrier 强制两线程 copy 阶段重叠） | 进程内 | 无异常；目标内容为完整 A（4MB 使窗口稳定）；无 `.tmp-*` 残留 |
| push 同名目标 FileExistsError 短路 | 进程内 monkeypatch | 退 `existing` 语义，`errors == []` |
| config 原子写不留残file | 进程内 | 写成功无 `*.tmp-*`；注入 replace 失败后原 config 完好、无残留 |
| 持连接时 rebuild --from-archives（subprocess 持库 25s） | 子进程 | 重试耗尽退 1；`error` 含"原索引未改动"；doctor 复核 stats 完好；无 `.staging*` |
| 三进程并发全量重建 | 子进程 | 全部退 0；无 `.staging*` 残留；`bak-*` 数量 ≤ 成功换入次数（无孤儿爆炸）；doctor stats 精确 |
| 四进程并发 import 同库 | 子进程 | 全退 0；doctor stats == (2 会话/4 消息)；重跑一次不翻倍 |

子进程用例复用 Spec 8 的 `_run` 手法（`cwd` 仓库根、UTF-8 双保险、
`timeout=60`；持库 holder 用后即杀）。运行时长预算：+6 条合计 < 90s。

## 6. 风险与决策

1. **不引锁的边界**：若后续出现重试无法收敛的场景（如同一同步目录挂
   网络盘出现毫秒级以上的持续共享冲突），再议锁，不预支复杂度。
2. **`.bak-<时间戳>` 无自动清理**：磁盘占用以"次数×库大小"线性累积。
   接受：本工具库体量小（MB 级）、重建低频；自动清理另议。
3. **Windows 专属重试**：POSIX 上 `os.replace` 本就不报共享冲突，重试
   循环空转成本可忽略，不做平台分支。
4. **同进程多线程同名 push**：临时名含 pid，同进程两线程仍可能同临时
   路径——但 CLI 是单线程模型，测试用 barrier 的用例断言"内容与无残留"
   即可，不为线程模型加码。
