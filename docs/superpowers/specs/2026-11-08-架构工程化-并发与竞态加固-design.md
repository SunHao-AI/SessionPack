## 1. 背景与问题

本工具的设计前提是"单机、双设备、经同步目录交换"，但没有任何一处
禁止（也没有测试约束过）两个进程同时操作同一数据目录或同一同步目录。
立项探针在 Windows 上实测出两类真实缺陷、一类"已经安全"、一处顺带
发现：

| 编号 | 场景 | 实测结果 |
|------|------|----------|
| F1 | 两进程 push 同名包到同一同步目录 | **缺陷**：4 进程并发 push 退码 `[0,1,0,1]`，虚假失败 |
| F2 | 他进程持连接时 `rebuild --from-archives` | 失败模式优雅：`换入失败，已回滚，原索引未改动`，退 1，原库完好、无 staging 残留（但此不变量无回归测试锁定） |
| F2b | 三进程同时 `rebuild --from-archives` | **缺陷**：退码 `[1,0,1]` 且数据目录残留**两个 `.bak`**，其中一个是孤儿（库完好、stats 正常） |
| F3 | 四进程同时 import 同一库 | 安全：全部退 0，stats 精确收敛（2 会话/4 消息），重跑幂等不翻倍 |
| 顺带 | config.toml 写失败残留 | `set_sync_dir` 本就是"临时文件 + `os.replace`"原子写（草案初判"直接 write_text 非原子"有误，逐字对现场后修正），真实缺口仅在 `os.replace` 失败后 `.tmp` 残留 |

## 2. 根因（逐字对现场）

1. **F1**：`sync._atomic_copy` 的临时名固定为 `".tmp-" + dest.name`
   （[sync.py](../../../sessionpack/sync.py) L46），**不含写者标识**。两个
   写者推同名包时临时路径完全相同：互相覆盖半成品，`finally` 里
   `tmp.unlink(missing_ok=True)` 还会删掉对方的在途临时文件；Windows 上
   `os.replace` 撞上他进程正持有的临时文件句柄直接抛
   `PermissionError [WinError 32]`。
   注：同名包内容必相同（文件名尾 12 位是内容 sha256，
   `compute_archive_id`），所以损害限于**虚假失败与在途互踩**，
   不存在静默内容损坏（探针 4MB 重叠写实测目标内容恒为完整 A 或完整 B）。
2. **F2b**：换库序列"原库→`.bak`（先 `unlink` 旧备份）、staging→原库"
   无写者协调。两个重建进程交错时，输家的 `.bak` 成为孤儿；且赢家换入
   瞬间输家的 `_cleanup_sidecars_only` 会误删赢家的 `-wal`。
3. **F3 安全的原因（要保住，不许退化）**：`busy_timeout=5000` + 每文件
   一事务 + 全表 UPSERT 幂等。
4. **config**：`set_sync_dir` 已是原子写（临时文件 + `os.replace`），
   唯一缺口是 `os.replace` 失败（如目标被占）后 `config.toml.tmp` 残留。

## 3. 目标与非目标

目标（全部最小修复，不引入守护进程与外部依赖）：

- **R1 push/pull 临时名写者唯一**：`.tmp-<目标名>.<pid>.<uuid4 前 8 位>`。
  必须保留 `.tmp-` 前缀——`_TEMP_PREFIXES` 的"临时文件不当真包"
  语义与既有测试（`test_sync.py` 的 `.tmp-*` 断言）依赖它。
  同名目标竞态的良性结局：`os.replace` 抛 `PermissionError`
  （Windows 目标被他进程持有，实测 WinError 32；POSIX 语义下则为
  `FileExistsError`）且目标已存在时，视作"已由他人落定"消化不报错
  （同名包内容必同），目标不存在则原样上抛。push/pull 均同此处理。
- **R2 换库竞态收敛**：换入与回滚恢复的 `os.replace` 统一走
  `_replace_with_retry`——捕 `PermissionError`，5 次 × 0.2s 退避
  （专治 Windows 共享冲突），重试尽仍失败走既有回滚路径，文案不变；
  回滚恢复自身失败时**保留 `.bak`（唯一副本绝不删除）**并返回含
  手工归位指引的错误，不崩栈。
  偏差记录：草案原计划 `.bak` 改名 `.bak-<UTC 时间戳>`，实施时逐字
  复核发现被既有测试锁死（`test_cli_commands.py` L457/L482 断言精确
  文件名），按"既有测试不改"精神放弃改名、保留 `catalog.sqlite.bak`。
- **R3 config 写失败不留残file**：`set_sync_dir` 已是原子写，仅补
  `os.replace` 失败路径 `tmp.unlink(missing_ok=True)` 后上抛。
  临时名 `config.toml.tmp` 保持不动（被 `test_config.py` 断言锁死）。
- **R4 回归测试**：把 F2 的优雅结局与 F3 的幂等收敛从"探针实测"升级为
  测试锁定；探针用过的三组竞态各有对应测试。

非目标：

- 进程间互斥锁/单实例锁（文件锁、`msvcrt.locking`）——重试 + 幂等已
  覆盖实测缺陷，锁带来的死锁/残留锁问题超出问题规模。
- 性能基准（另议，维持 Spec 8 决定）。
- WebDAV/网络盘的竞态（同步载体仅本地目录，与 Spec 8 一致）。
- 多线程（同进程）并发调用的支持承诺——只测多进程。

## 5. 设计

### 5.1 R1：sync._atomic_copy（sync.py）

```python
def _atomic_copy(src: Path, dest: Path) -> None:
    dest.parent.mkdir(parents=True, exist_ok=True)
    tmp = dest.parent / (
        f".tmp-{dest.name}.{os.getpid()}.{uuid.uuid4().hex[:8]}")
    try:
        shutil.copy2(src, tmp)
        os.replace(tmp, dest)
    except (PermissionError, FileExistsError):
        # 目标正被他进程持有（同名包内容必相同）：目标已存在即
        # "已由他人落定"，良性消化；否则原样上抛。
        if not dest.exists():
            raise
    finally:
        tmp.unlink(missing_ok=True)
```

调用侧语义核对：`push_archives`/`pull_archives` 现有 `except OSError`
收集错误的分支不动（真 IO 错误仍上报）；良性竞态在函数内消化，
不计 errors。pull 侧同名短路的既有语义保持。

### 5.2 R2：换库重试与回滚加固（rebuild.py）

- 换入的两处 `os.replace`（原库→`.bak`、staging→原库）与回滚恢复
  统一走 `_replace_with_retry(src, dst)`：捕 `PermissionError`，
  0.2s × 5 次退避重试，仍失败原样抛出走既有回滚。
- `.bak` 名称保持 `catalog.sqlite.bak` 不动——被既有测试锁死
  （`test_cli_commands.py` L457 `backup.name == "catalog.sqlite.bak"`、
  L482 不存在性断言）。放弃草案的改名方案（偏差见 §3-R2）。
- 回滚恢复自身失败（`.bak` 也被占用）时：不删 `.bak`（唯一副本），
  返回"备份暂被他进程占用…手工改名回去即可"的明确错误，不崩栈。

### 5.3 R3：config 写失败不留残file（config.py）

`set_sync_dir` 已是"临时文件 + `os.replace`"原子写（草案误判已修正），
仅补：`os.replace` 抛 `OSError` 时 `tmp.unlink(missing_ok=True)` 后上抛。
临时名与 `ConfigWriteError` 保真校验契约均不动（Spec 6 CFG-1 测试不动）。

### 5.4 R4：测试（tests/test_race_concurrency.py，+6）

| 用例 | 层 | 断言 |
|------|----|------|
| 重叠写同名目标（barrier 强制两线程 copy 阶段重叠） | 进程内 | 无异常；目标内容为完整 A（4MB 使窗口稳定）；无 `.tmp-*` 残留 |
| push 同名目标良性竞态消化 | 进程内 monkeypatch | replace 抛 PermissionError 且目标已存在 → `errors == []`、目标内容完好；目标不存在 → 原样上抛进 errors |
| config replace 失败不留残file | 进程内 | 写成功无 `config.toml.tmp`；注入 replace 失败后原 config 完好、无残留 |
| 持连接时 rebuild --from-archives（subprocess 持库 25s） | 子进程 | 重试耗尽退 1；`error` 含"原索引未改动"；doctor 复核 stats 完好；无 `.staging*` |
| 三进程并发全量重建 | 子进程 | 不变量：≥1 进程退 0；全部进程或退 0 或给出"原索引未改动"类干净失败；无 `.staging*` 残留；`.bak` 数量 ≤ 1（无孤儿爆炸）；doctor stats 精确 |
| 四进程并发 import 同库 | 子进程 | 全退 0；doctor stats == (2 会话/4 消息)；重跑一次不翻倍 |

注（草案偏差）：三进程并发重建不承诺"全部退 0"——staging 为固定名
`catalog.sqlite.staging`，并发重建者在 staging 上仍会互踩（F2b 实测
"attempt to write a readonly database"的根因），收敛为上述**不变量**
断言：赢家成功、败者干净失败且不留任何脏状态。

子进程用例复用 Spec 8 的 `_run` 手法（`cwd` 仓库根、UTF-8 双保险、
`timeout=60`；持库 holder 用后即杀）。运行时长预算：+6 条合计 < 90s。

## 6. 风险与决策

1. **不引锁的边界**：若后续出现重试无法收敛的场景（如同一同步目录挂
   网络盘出现毫秒级以上的持续共享冲突），再议锁，不预支复杂度。
2. **`.bak` 无自动清理**：改名方案被测试锁死放弃后，`.bak` 仍为固定名
   单份覆盖，不存在累积问题；F2b 的孤儿备份竞态由重试大幅收窄
   （不承诺根除，见 §5.4 不变量注）。
3. **Windows 专属重试**：POSIX 上 `os.replace` 本就不报共享冲突，重试
   循环空转成本可忽略，不做平台分支。
4. **同进程多线程同名 push**：临时名含 pid，同进程两线程仍可能同临时
   路径——但 CLI 是单线程模型，测试用 barrier 的用例断言"内容与无残留"
   即可，不为线程模型加码。
