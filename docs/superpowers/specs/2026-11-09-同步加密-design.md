# Spec 14：同步目录端到端加密（C1）

日期：2026-11-09　状态：待审阅

## 1. 背景（勘察实测）

- 同步目录（`[sync].dir`）通常挂在网盘/NAS 客户端下，云服务商技术上可读全部文件。
  现归档包是明文 zip，含会话标题、摘要、消息全文（`使用说明` L77 已如实警告）。
- `sessionpack/sync.py`（174 行）：
  - `_scan_zips` L38-44 只扫 `*.zip` 且排除 `.tmp-`/`.build-` 前缀；
  - `push_archives` L90-123 用**文件名同名**判重（`src.name in remote_names`）后 verify → `_atomic_copy`；
  - `pull_archives` L126-174 用文件名尾 12 位 `_id_tail` + 文件名判重，verify 后复制 → `import_archive`；
  - `find_archives_with_session` L47-69（Spec 13 D6 purge 报告用）只读打开同步目录明文 zip 探测会话内容。
- `sessionpack/config.py`：`[sync].dir` 读写；`set_sync_dir` L133 合并式写回 + `_unfaithful` 保真校验 fail-closed；`_toml_value` 已支持 bool。
- `sessionpack/archive/build.py`：`archive_id` = 包内文件 sha256 串联哈希；包名 `{slug}-{date}-{id[:12]}.zip`。
- ADR-007 L81 预留："在这层外面套一个加密信封，内部结构不需要改动"——本 Spec 即兑现此预留位。
- 全仓无任何口令/getpass 先例；`pyproject.toml` `dependencies = []`。

## 2. 目标 / 非目标

**目标**

1. push 到同步目录的包整体加密为不透明信封 `.spk`：网盘侧看不到项目名、日期、会话内容中的任何一项。
2. pull 端口令解密后走既有 verify + import 流程，正确性与幂等语义不回退。
3. 口令派生密钥，密钥材料永不落盘；忘口令 = 同步目录内容不可恢复（用户已接受）。
4. 提供 `reencrypt` 一次性迁移命令，把存量明文 zip 同步目录转为信封。
5. 未开启加密时（默认）行为与现状字节级一致——零行为变更。

**非目标**

- 不做本机 archives 目录/数据库加密（本机信任模型不变）。
- 不做口令缓存、keyring、多口令、密钥轮换。
- 不做抗暴力破解的专门设计（口令强度风险用户自担，见 D1）。
- 不做信封内容的选择性解密（信封粒度 = 整包）。
- 不引入除 cryptography 外的任何第三方依赖。

## 3. 硬约束

1. **依赖裁决（本 Spec 唯一的运行时依赖例外）**：仅允许 `cryptography`（AESGCM + PBKDF2HMAC）。
   `pyproject.toml` `dependencies = ["cryptography>=42"]`。其余第三方仍禁止；守卫脚本仍仅 stdlib。
   文档中"零运行时第三方依赖"表述需同步修订为"唯一例外：cryptography（同步加密）"。
2. 沿 Spec 7-12：`scripts/check.py` 全绿（lint_imports / ruff / mypy / pytest），BASELINE 与 E_SQL 白名单不动，不写 CI，`spike/` 不动。
3. 包格式（zip + manifest、FORMAT_VERSION=1、archive_id 算法）零改动；`archives/` 本机文件名与导入语义零改动。
4. 现有 327 项测试全过；不开加密模式时，sync 行为与 Spec 13 落地态完全一致。

## 4. 设计

### D1 威胁模型与信任边界

防的是**不可信存储**（网盘/云服务商能拿到同步目录全部字节与文件名）。
口令强度风险用户自担，不做 KDF 之外的抗暴破设计（无锁定、无口令策略强制）。
本机文件系统视为可信：口令只经内存，密钥材料不落盘、不写日志、不进报告。

### D2 依赖与模块落位

- 新增 `sessionpack/crypto.py`：**L0 纯函数层**，`lint_imports.py` 的 `LAYER_OF` 登记 `"crypto": 0`。
  该模块是唯一允许 import `cryptography` 的文件（新增守卫规则见 §5）。
- 接口（全部纯函数、无状态）：

```python
def derive_key(passphrase: str, salt: bytes, iterations: int) -> bytes
def encrypt_envelope(plaintext: bytes, passphrase: str) -> bytes
def decrypt_envelope(blob: bytes, passphrase: str, name: str) -> bytes
```

  - `encrypt_envelope` 自生成 16B 随机 salt，输出头部含 format/salt/iterations/12B nonce + AESGCM ciphertext；
  - `decrypt_envelope` 校验头部 magic `SPKE1` 与版本字节，失败抛 `EnvelopeError`；`name` 作为 AAD 参与认证（见 D5）；
  - PBKDF2-HMAC-SHA256，迭代 **600_000**，写在信封头部（未来可升迭代而不破坏旧信封）。
- `sync.py`（L3）import `crypto`（L0）合法；CLI 层负责口令采集后传参，`crypto.py` 与 `sync.py` 均不读环境变量、不交互。

### D3 信封格式（.spk）

```
offset  size  字段
0       5     magic "SPKE1"
5       1     格式版本 = 0x01
6       16    salt（PBKDF2，每信封随机）
22      4     iterations（大端 uint32，当前 600000）
26      12    AESGCM nonce（每信封随机 96-bit）
38      N     ciphertext（内含 16B GCM tag）
```

- 明文 = verify 通过的 zip 原始字节，整包一次加密（包体量级 <百 MB，无需分块）。
- 每次加密 salt/nonce 全新随机：同一 zip 两次加密字节不同，云侧无法判同。

### D4 口令获取

`sessionpack/cli/write_cmds.py` 内统一 helper `_passphrase(prompt: str) -> str | None`：
先看环境变量 `SESSIONPACK_PASSPHRASE`（非空即用，供脚本/计划任务）；否则 `getpass.getpass` 交互输入两次一致后返回。
不一致或两次均为空 → 返回 None，调用方出 `CommandResult` 失败提示，不进入加解密。无缓存、无 keyring。
`push`/`reencrypt`/`pull` 走此完整语义；`pull` 仅在同步目录发现 `.spk` 时才触发采集（纯明文目录不询问口令）；`purge` 的调用方用宽松变体（仅取环境变量，无则视为未提供口令，见 D9）。

### D5 元数据最小化与 AAD 绑定

- push 写信封文件名为 `spk-<32hex>.spk`（`secrets.token_hex(16)`），项目名/日期/12 位 id 全部只存在于密文内。
- **AAD = 信封文件名字节**（如 `b"spk-….spk"`）：把文件名传给 `decrypt_envelope` 的 `name` 参数。云侧或任何中间人改名、替换、重排信封 → GCM 认证失败，pull 报 `skipped_invalid` 而非静默导入错内容。
- 判重语义随之改变：信封文件名每次随机，**push 侧旧的"文件名同名判重"（sync.py L98-101）在加密模式下失效**，必须与 pull 侧统一为**解密后按 `archive_id` 判重**（见 D6）。

### D6 sync.py 改造（push / pull）

`push_archives` / `pull_archives` 增加参数 `encrypt: bool = False, passphrase: str | None = None`（由 CLI 层从 `[sync].encrypt` + D4 取得）。

- **push（encrypt=True）**：
  1. 收集同步目录既有信封：逐个 `decrypt_envelope` 取内层 zip 的 `archive_id`（解密失败的文件计入 `skipped_invalid` 不阻塞）；本机包已 verify 过（沿用现门禁）后取其 `archive_id`；
  2. `archive_id` 已在场 → `skipped_existing`；
  3. 不在场 → `encrypt_envelope(zip_bytes, passphrase)` → `_atomic_copy` 落 `.tmp-*` 临时名再原子改名为 `spk-<新随机hex>.spk`（复用既有 `_atomic_copy`，临时前缀语义不变）。
  4. 解密判重成本：每信封一次 PBKDF2（600k 迭代约 0.3-0.5s）。同步目录包数量级为几十，可接受；派生密钥按 (salt, iterations) 每文件独立，无跨文件复用（信封 salt 各不相同，本就不可复用）。
- **pull（口令模式）**：对同步目录 `*.zip` 走现状路径（明文兼容）；对 `*.spk` 先 `decrypt_envelope` 得 zip 字节 → 落临时 zip 文件 → 走既有 `verify_archive` → 按 `archive_id` 与本机 `archives/` 判重（`_id_tail` 集合）→ 通过后原子复制到本机规范包名 → `import_archive`。解密失败/认证失败 → `skipped_invalid`。口令错误时全部 `.spk` 归入 `skipped_invalid`，报告首条附"口令错误或文件损坏"提示。
- `_scan_zips` 扩展为 `_scan_sync_candidates`：`*.zip` + `*.spk`（仍排除 `_TEMP_PREFIXES`）；本机 `archives/` 目录扫描仍只看 `*.zip`。
- 判重与幂等：同 `archive_id` 的包可能对应多个不同文件名的信封（两台设备各推一次）——pull 解密判重后 `skipped_existing`，push 判重后不再推。云侧冗余信封不删除（只增不删原则不变）。

### D7 配置开关

- `config.toml` 新增 `[sync].encrypt = true|false`，默认缺省 = false。
- `config.py` 新增 `sync_encrypt(root) -> bool` 与 `set_sync_encrypt(root, value: bool)`；写回完全复用 `set_sync_dir` 的合并式写回 + `_unfaithful` 保真校验 fail-closed 模式（`_toml_value` 已支持 bool）。
- CLI：`push --dir D: --encrypt` / `--no-encrypt` 显式覆盖并持久化（沿用 push 成功后写 `dir` 的既有行为）；不带开关时读配置。pull 不看该键（pull 按文件后缀自适应）。

### D8 `reencrypt` 迁移命令

`sessionpack reencrypt [--dir DIR]`：一次性把同步目录明文 zip 转为信封。
1. 口令按 D4 采集；目录取 `--dir` 或配置；
2. 对每个明文 zip：verify 不过 → 跳过并报告；
3. 加密写 `.tmp-enc-*` → 立即解密自检（解密 → 与原 zip 字节级相等）→ `os.replace` 改名为随机 `spk-*.spk` → 删除原 zip；
4. 自检失败：删临时信封、保留原 zip、报告错误（fail-safe，原包永不在自检通过前被删）；
5. 已是信封的文件跳过；结束打印 converted/skipped/errors 计数。

### D9 purge 报告失明（`find_archives_with_session`）

同步目录加密后该函数（sync.py L47-69，`purge` 完成后列出"仍含该会话内容的包"）对 `.spk` 失明。裁决：**扩展为可选口令解密扫描**——签名加 `passphrase: str | None = None`；为 None 时行为不变（只扫明文 zip）；purge 命令在 `[sync].encrypt` 开启时取 `SESSIONPACK_PASSPHRASE`（宽松变体，不强制交互输入）传入，逐信封解密后扫描（解密失败按"不含"跳过，维持现"宁漏勿错"取态）。口令未提供时报告附一行提示"同步目录含加密信封，未扫描"。

## 6. 错误处理与边界

| 情形 | 行为 |
|---|---|
| 口令错误 pull | 全部 `.spk` → `skipped_invalid`，报告含"口令错误或文件损坏" |
| 信封被改名/截断/篡改 | AAD/GCM 认证失败 → `skipped_invalid`，不产生本机文件 |
| magic 不是 SPKE1 / 版本未知 | `EnvelopeError` → `skipped_invalid`（前缀识别，不误当 zip） |
| `.spk` 与 `.zip` 同 archive_id 并存（迁移中间态） | 任一先导入，另一按 `skipped_existing`；导入层幂等兜底 |
| push 时同步目录信封解密失败 | 计入报告 `skipped_invalid`，不阻塞其余包推送 |
| `reencrypt` 自检失败 | 删临时信封、原 zip 原位保留、非零退出 |
| `SESSIONPACK_PASSPHRASE` 与交互并存 | 环境变量优先（脚本场景静默非交互） |
| 加密模式 + `--dry-run` | 完整走判重（含解密），不落任何文件 |
| 空口令 | 拒绝（与两次输入不一致同路径报错） |
| 同步目录不可写 / 单文件失败 | 沿用现状：单包 `errors`，其余继续 |

## 10. 落地记录

- 信封头定长 **38B**（magic 5 + ver 1 + salt 16 + iter 4 大端 + nonce 12）；计划文中"48"为笔误，以实现与测试为准。
- KDF：PBKDF2-HMAC-SHA256 默认 **600_000** 轮；解密侧校验区间 `[1, 5_000_000]`，越界在派生前抛 E202（拒绝解密侧无界开销）。
- AAD 绑定信封文件名字节：改名、换名重放一律 GCM 校验失败（E202）。
- 信封名判定单一来源 `crypto.is_envelope_name`（宽松：前缀 `spk-` + 后缀 `.spk`；`spk-<32hex>.spk` 是 `new_envelope_name` 的产出格式），sync 层与 CLI pull/purge 探测全部转发，不再各写前缀后缀拼接；reencrypt 只扫 `*.zip` 明文包，无信封探测；purge 与 pull 的扫描面收敛到该公开判定，点号前缀杂散文件不进报告属有意统一。
- 依赖例外落地：`cryptography` 为唯一运行时第三方依赖，README 与设计文档"零依赖"表述已改；E_CRYPTO 规则封堵 `cryptography` 三种 import 拼写，仅放行 `sessionpack/crypto.py`。
- reencrypt 迁移顺序 fail-safe：先写临时信封 → `os.replace` 原子就位 → 再删原明文包；删除失败单独记"信封已就位，原明文包删除失败"，原包保留可幂等重试。
