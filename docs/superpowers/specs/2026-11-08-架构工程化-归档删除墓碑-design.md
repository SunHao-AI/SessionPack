## 1. 背景（勘察实测）

| # | 事实 | 含义 |
| --- | --- | --- |
| P1 | **全仓库没有任何删除会话的代码路径**：无 DELETE FROM sessions、无 CLI 入口；同步两端只增不删 | "误删扩散"当前不可能发生，但也没有用户需要的删除能力；本 Spec 同时补能力和护栏 |
| P2 | `sessions.status` 是**死列**：SCHEMA 定义 `NOT NULL DEFAULT 'active'`（conn.py L49），全仓库只有 `build.py` L102 读出写进 meta.json，install 完全忽略 | 墓碑有现成挂载点，**无需 schema 迁移** |
| P3 | meta.json 已含 `status` 字段且参与 sha256/`archive_id`；ADR-007：新增可选字段不递增 `format_version`，破坏性变更才算 | 墓碑**零格式版本变更**：status 写 `"deleted"` 即墓碑 |
| P4 | `upsert_message` 对已存在会话只 UPDATE `project_id/updated_at`，**从不写 status**（write.py L111-116）；`upsert_topic` 只 INSERT 缺的 sessions 行 | "墓碑优先"在现有写入路径上天然成立，无需额外比较逻辑 |
| P5 | pull 判同只看包名（同名必同内容，尾 12 位是内容 sha256）；墓碑会话改变 meta 内容 → 墓碑包必是新名字 | 墓碑包与旧 active 包**共存于同步目录**，无同名冲突；旧包不会被墓碑包覆盖 |
| P6 | 读侧无任何 status 过滤：`list_sessions`、`get_session`、`search_messages`（两分支均不 JOIN sessions）、`get_projects` 的 `session_count`、`stats` 全局计数 | 删除要对用户视图生效，需在列表/详情/检索/项目计数四处补过滤 |
| P7 | `run_export --archive` 直接走 `build_archive`（全表查询含墓碑）；`list_sessions(limit=1)` 守卫只在 `--project` 明文导出路径（L123） | 全墓碑项目**已经**能导归档包，守卫无需修改；明文导出隐藏墓碑恰是正确行为。以回归测试锁定 |

## 2. 目标 / 非目标

**目标**
- G1 本机删除入口：`sessionpack delete --session ID`（软删墓碑，消息保留）与 `--undo`（本机撤销）。
- G2 删除经 export → push → pull 传播：任何设备（含已持有该会话的设备、全新设备）导入墓碑包后会话不出现、不复活。
- G3 墓碑优先裁决：墓碑一旦落下，导入任何 active 数据（含删除之前生成的旧归档包）都不复活；撤销只在本机。
- G4 删除内容在列表/详情/检索/项目计数中隐藏，undo 后恢复；
  `stats`/doctor 保持**物理计数**（重建自检与 FTS 对账依赖物理真相，
  且"删除=隐藏不复活、不抹除"下物理行本就不变）。

**非目标**
- 物理清除（真删消息行与归档文件）：与"归档是不可丢的持久副本"（ADR-007）冲突，另立 Spec。删除=隐藏+不复活，**不是抹除**；同步目录中的历史包仍含全文。
- 撤销跨设备传播：墓碑优先则撤销必然不可传播（否则退化为"最后写入者胜"），接受此限制并在文案中明示。
- 冲突时间戳比较、schema 迁移、format_version 升版、版本号递增。

## 4. 设计

### D1 catalog 写侧：墓碑与撤销（catalog/write.py）

- `mark_session_deleted(conn, session_id, *, now) -> bool`：会话不存在返回 False；存在则
  `UPDATE sessions SET status='deleted', updated_at=?`（幂等，重复标记仍 True）。
- `restore_session(conn, session_id, *, now) -> bool`：仅当当前 `status='deleted'` 才置回
  `active` 并刷新 `updated_at`，否则 False。
- 消息行与 message_fts **不动**——隐藏靠读侧过滤，撤销零成本。
- 两函数经 `catalog/__init__.py` 导出。

### D2 catalog 读侧：视图过滤（catalog/read.py）

- `list_sessions`：clauses 恒置入 `s.status != 'deleted'`（拼接处注意首个条件无 WHERE 前缀的现有结构）；
- `get_session`：WHERE 追加 `AND s.status != 'deleted'`（详情 404 / CLI"会话不存在"）；
- `search_messages` 两分支过滤：FTS 分支追加
  `JOIN sessions s ON s.session_id=m.session_id AND s.status != 'deleted'`；
  LIKE 分支追加
  `AND session_id IN (SELECT session_id FROM sessions WHERE status != 'deleted')`；
- `get_projects` 的 `session_count`：LEFT JOIN 条件追加 `AND s.status != 'deleted'`；
- `stats` **不过滤**——doctor 与 rebuild 自检（rebuild.py L165-168）依赖物理计数，
  墓碑保留物理行本就是设计语义；
- `export_session/export_project/export_all` 全部走 get_session/list_sessions，自动隐身，零改动。
- Web 前端零改动：`/api/sessions`、`/api/session`、`/api/search` 走上述 API。

### D3 归档协议：零升版（archive/build.py 零改动）

`build_archive` 本就导出全部会话且 meta 含 status，墓碑自动进包；
`counts.sessions` 含墓碑属如实计数，不改语义。

### D4 安装侧：墓碑落实（archive/install.py）

每个会话在 `upsert_topic/upsert_message` **之前**先落实 status（顺序关键，否则两个
upsert 会在新库上把会话建成 active）：

- meta `status == "deleted"`：调用 `catalog.mark_session_deleted`（缺会话先 INSERT
  墓碑行——新库也要有此墓碑，才能挡住后续任意旧包导入复活）；
- 其余（缺失/`active`/未知值）：不动 status；未知值按 active 数据处理（读侧只显示非 deleted，
  与缺失同语义，符合"忽略不认识的值"）。

墓碑优先由 P4 天然保证：墓碑落实后，任何 active 导入都碰不到 status 列。

### D5 CLI：delete 子命令（cli/parser.py + cli/write_cmds.py）

```
sessionpack delete --session ID [--undo] [--data-dir DIR] [--json]
```

- 删除成功文案：`已删除会话 <id>（本机视图隐藏；export --archive + push 后，
  删除将随归档包传播且不会因旧包复活）`；
- `--undo`：本机恢复；文案明示撤销**不跨设备**（他机若已导入墓碑包，不受本机撤销影响）;
- 会话不存在 / undo 时并非 deleted 状态 → EXIT_USAGE；
- help 短语：`软删除会话（墓碑，随归档包传播不复活；--undo 仅撤销本机）`。

### D6 导出路径回归（零改动）

`--archive` 路径不经 `list_sessions` 守卫（P7），全墓碑项目天然可出墓碑包；
`--project` 明文导出的守卫隐藏墓碑属正确行为。两处均由 F-2 回归测试锁定，不改代码。

### D7 文档

README 命令速览加 delete 行；`docs/使用说明-本地只读.md` 增"删除与撤销"小节
（墓碑传播语义、不抹除、撤销仅本机）；push/pull 的"只增不删"帮助保持不变（指文件不删，
语义仍准确）。

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 本机 undo 后他机永久 deleted（撤销不可传播） | G3 用户选定的语义；help/README/文案三处明示 |
| 墓碑包的 messages.ndjson 仍含全文（删除≠抹除） | 非目标明示；历史包本就不可删（ADR-007），物理清除另立 Spec |
| 墓碑 updated_at 与消息 ts 的字符串 MAX 比较 | 同为 `%Y-%m-%dT%H:%M:%S` 风格，字典序=时间序；updated_at 仅展示用，语义已宽松 |
| 读侧过滤遗漏某处 | F-2 以 API 为断言面：过滤收敛在 read.py 四处（list/get/search 两分支/get_projects），`stats` 有意不过滤；测试直接锁 API |
