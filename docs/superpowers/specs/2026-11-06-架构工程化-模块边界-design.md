## 1. 背景与目标

Spec 1 建立了 ruff→mypy→pytest 护栏链。本 spec 解决模块间边界问题：
越层调用、私有符号跨模块引用、schema 知识分裂、巨文件巨函数。

目标（按已确认的四项决策）：

1. 修复范围 = P1–P5 全收（次要项进"已知遗留"，见 §7）。
2. 重构形态 = 彻底物理拆包（archive 拆包目录）。
3. 边界固化 = 自写守卫脚本 `scripts/lint_imports.py` 挂进 check.py 主链。
4. 迁移节奏 = 每个 P 一个 commit，每步护栏全绿。

### 硬约束（延续 Spec 1）

- 对外契约硬锁：manifest format_version=1、config.toml 格式、CLI 命令与参数、
  HTTP 端点、`sessionpack.archive.X` 等包内公共 import 路径均不变。
- 零运行时第三方依赖（守卫脚本仅 stdlib）。
- 不写 CI；`spike/` 不动；main 本地 commit 不推送。
- 144 个既有测试保持全绿，不删不改断言（archive 拆包后测试 import 路径不变）。

## 3. 目标模块结构与分层规则表

### 3.1 目标结构（新增 3 处，其余 16 模块名不变）

```
sessionpack/
├── model.py  paths.py  audit.py  mem.py  summary.py  config.py   ← 叶子层不动
├── textutil.py          ← 新增：failure_text()（原 archive._failure_text 迁入）
├── catalog.py           ← 增量：import_runs/import_files 读写 API（§5.1）
├── adapters/
│   ├── base.py          ← 协议补 display_name 槽位（§4.2）
│   ├── trae_memory.py   ← 实现槽位；SESSION_FILE_RE 等保持模块私有
│   └── __init__.py      ← get_adapter() -> MemoryAdapter（返回协议类型）
├── archive/             ← 单文件拆为包
│   ├── __init__.py      ← 重导出全部公共符号，对外 import 路径不变
│   ├── format.py        ← FORMAT_*/MANIFEST_NAME、ArchiveResult/VerifyIssue/VerifyResult/
│   │                      ArchiveImportResult/ArchiveError、compute_archive_id、
│   │                      _slug/_unsafe_member/_sha256_* 等编解码原语
│   ├── build.py         ← build_archive
│   ├── verify.py        ← verify_archive
│   └── install.py       ← import_archive（SQL 改走 catalog API）
├── export.py            ← +公开 render()
├── importer.py          ← 删私有导入、删 SQL，变纯编排
├── sync.py  diagnostics.py  server.py  cli.py   ← 调用点改公开 API
```

### 3.2 分层规则表（守卫脚本的白名单依据）

| 层 | 模块 | 允许的出边 |
|----|------|-----------|
| L0 叶子 | model, paths, audit, mem, summary, config, textutil | 无（仅 stdlib） |
| L1 适配 | adapters/* | L0 |
| L2 数据 | catalog | L0（model） |
| L3 领域 | archive, export, importer, sync, diagnostics | L0–L2 |
| L4 入口 | cli, server | L0–L3 |

横切禁令（比层级更严，任何层适用）：

1. **私有符号禁令**：任何模块不得引用他模块 `_` 前缀符号
   （`from x import _y`、`x._y` 均违规）。
2. **SQL 独占令**：涉及业务表（projects/sessions/messages/import_runs/
   import_files/message_fts）的 SQL 只允许出现在 catalog.py
   （archive install 段与 importer 的现存违例在本 spec 内清零）。

对外契约核验：`sessionpack.archive.X` 经包 `__init__` 重导出后不变；
CLI/HTTP/manifest/config 全部不触碰。

### 4.4 P4：SQL 收敛 + importer 分解

catalog.py 新增 API（表知识唯一归宿）：

```
begin_import_run(conn, run_id, adapter_id, adapter_version, started_at) -> None
finish_import_run(conn, run_id, *, finished_at, result,
                  scanned_files=None, imported_rows=None,
                  failed_rows=None, warnings_json=None) -> None
    # 只 UPDATE 传入了非 None 值的列，覆盖 archive install 的失败路径写法
load_import_files(conn) -> dict[str, sqlite3.Row]        # key = path 列
register_import_files(conn, rows: list[tuple[str, int, float]]) -> None  # INSERT OR IGNORE
reset_import_file(conn, *, size, mtime, path) -> None    # 变更重置
clear_import_file_error(conn, path) -> None              # retry_failed 清零
save_import_file_state(conn, *, path, offset, rows, done,
                       last_run_id, error) -> None       # 断点写回
```

- importer 的全部 7 处裸 SQL（L112 INSERT import_runs、L136 SELECT import_files、

- `import_source` 拆为同文件私有步骤函数（如 `_plan_files`、`_process_file`、

## 5. 守卫脚本 scripts/lint_imports.py

- 纯 stdlib（`ast` 解析 `sessionpack/**/*.py`），输出 `文件:行: 规则名 说明`，
  违规非零退出；挂进 check.py 的 `ORDER` 首位（最便宜先跑）。
- 规则实现：
  1. 层级白名单：import 语句解析为 (源模块层 → 目标模块层)，
     边不在 §3.2 表内则违规。
  2. 私有符号：FromImport 中 `_` 前缀名；Attribute 访问 `mod._x`
     （mod 解析为 sessionpack 内模块名时）。
  3. SQL 独占：非 catalog.py 文件中，字符串常量含
     `(INSERT|UPDATE|DELETE FROM|CREATE TABLE).*(projects|sessions|messages|
     import_runs|import_files|message_fts)` 则违规。
- **基线机制**（沿用 Spec 1 mypy 宽基线风格）：脚本带 `BASELINE: list[str]`
  （条目=违规指纹），落地 commit（C1）时基线收录当时全部现存违规
  （P1/P2/P5/sync 私有调用等），保证当天全绿；此后每个 P commit
  必须同步删除对应基线条目——每个 P 的完成有机械证明。基线只减不增。
