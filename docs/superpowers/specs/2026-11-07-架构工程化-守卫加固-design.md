## 2. P2（仅 FP 侧）：`_rebound_names` 补收集推导式目标与 lambda 形参

### 现状复现

```python
src = "from sessionpack import archive\n[x for archive in y]\narchive._priv(1)\n"
# 现行为：报 E_PRIVATE '_priv' called on 'sessionpack.archive'
# （H2 探针）——推导式目标 archive 是局部迭代变量，链式访问的
# 是运行时元素而非模块，属误报。lambda 形参同理：
src2 = "from sessionpack import archive\n" \
       "list(map(lambda archive: archive._priv(1), objs))\n"
# lambda 体内 archive._priv 同样被误报。
```

FN 侧（G1/G2 探针：文件内任意一处 `def f(archive)` 或同名赋值即令
全文件该模块私有检查失效）维持 Spec 4 §3.2 的既有裁决不改——作用域
感知要求为每个 `Attribute` 访问做祖先作用域解析，stdlib 手写实现约
30+ 行且引入新的正确性面，收益（拦截"import 模块后又同名重绑定再
访问私有"的坏味道代码）不成比例。

### 方案

`_rebound_names` 的 `_add` 分发处补两个分支（各 2-3 行）：

- `ast.Lambda`：收集 `node.args` 全部形参（与 FunctionDef 同款展开）；
- `ast.comprehension`：`_add(node.target)` 收集 for/async for 推导式目标。

修复方向是**只放宽遮蔽判定（消 FP）**，即扩大 `rebound` 集合，
不新增任何报错路径；FN 面因此不会缩小（本就接受），FP 面消除。

### 验收

- 新增测试 ≥3：推导式目标遮蔽放行 / lambda 形参遮蔽放行 /
  未遮蔽时仍报（防止把 route C 整体放空）。
- 既有遮蔽测试
  （`test_private_rule_ok_module_name_rebound_to_instance` 等）不回归。

## 3. M-4：撤销——同包绝对导入豁免条款定为常驻机制

### 现状复现（探针 B1/B2，前提推翻的直接证据）

`_abs_from_import` 把相对导入按源模块所在包归一化为绝对点路径：

```python
# importer/run.py 内两种拼写归一化后 owner 同为 sessionpack.importer.plan：
run("from sessionpack.importer.plan import _commit_progress", ...)  # A1 clean
run("from .plan import _commit_progress", ...)                      # B1 clean
```

两种拼写的放行都依赖同一条 `owner.rpartition(".")[0] == pkg` 条款。
「改相对导入后条款即可收回」不成立：收回条款后 A1 **与** B1 都会报
E_PRIVATE（私有符号 `_commit_progress` / `_FileState` 等包内互导），
与拼写无关。若要条款自然失效，须改为私有符号公开命名或经门面中转，
那是为迁就守卫而扭曲包内设计，不值。

### 处置

- 不改代码。条款（`lint_imports.py` route D 与 from-import 分支中
  `pkg != "sessionpack" and owner.rpartition(".")[0] == pkg`）
  定性为**包内私有协作的常驻机制**，行为已被
  `test_package_intra_module_absolute_private_import_exempt` 与
  `test_flat_module_private_import_still_checked_after_I1` 双向锁定。
- Spec 4 §7 DEFER 清单中的 M-4 条目本文档宣告撤销；不回改已归档 spec
  （沿用 Spec 4 §5 backlog 校正惯例）。
- 全仓包内导入现状（Grep 实测）：importer/、archive/、catalog/、cli/、
  adapters/ 一律绝对拼写，importer/ 单独改相对反而破坏全局风格一致性
  ——这也是 M-4 原本动机关弱的旁证。

## 4. Minor-1 + Minor-2：门面属性链检测收窄

两处同根（`check_source` 的 `facade_roots` 块），一并修。

### 现状复现

**Minor-2（F1 探针，FP）**：形参遮蔽产生误报——

```python
src = "from sessionpack import cli\n\ndef handler(cli):\n    cli.output.render()\n"
# 现行为：报 E_DOM_IMPORT via attribute chain 'cli.output'
# 但 handler 内的 cli 是运行时对象，属性链与渲染层无关。
```

**Minor-1（M1a/M1b 探针，FP）**：`prefix in facade_roots` 对
「头绑定」与「重绑定」双重过宽——

```python
src = "import sessionpack.cli\nsessionpack = load_cfg()\nsessionpack.output()\n"
# M1a：sessionpack 已重绑定为配置对象，sessionpack.output() 仍被报。
src2 = "import sessionpack.cli\nsessionpack.output()\n"
# M1b：即便不重绑定，sessionpack.output 也不是渲染层
# （真实链是 sessionpack.cli.output，已由第二条件 f"{prefix}.output"
#  == RENDER_TARGET 全路径匹配覆盖）。`import sessionpack.cli` 把
# 本地名 sessionpack 登记为门面根，是 `prefix in facade_roots`
# 分支的过度匹配源头。
```

### 方案

在 facade 属性链判定处收窄两点，全部是**消 FP 方向**（不新增报错路径，
真阳性 `from sessionpack.cli import output` / `from
sessionpack.cli.output import X` / `sessionpack.cli.output.x` 不受影响）：

1. **尊重 `rebound`**（对齐 route C 既有政策）：属性链根名
   （`prefix.split(".")[0]`）在 `rebound` 集合中时保守放行。
2. **剔除头绑定根**：`facade_roots` 收录条件追加
   `n != o.split(".")[0]`——`import sessionpack.cli` 这类点路径导入
   把包首段绑进本地名，其真实门面链由全路径条件覆盖，无需登记为根；
   `from sessionpack import cli` / `import sessionpack.cli as c`
   这类叶子别名根仍照常登记。

### 验收

- 新增测试 ≥4：F1 形参遮蔽放行 / M1a 重绑定放行 / M1b 的
  `sessionpack.cli.output.x` 全路径真阳性仍报 /
  `from sessionpack import cli` + `cli.output()` 真阳性仍报。
- `test_dom_import_rule_hits_facade_attribute_chain*` 既有测试不回归
  （它们用 `from sessionpack import cli` 叶子别名拼写，属保留面）。

## 5. N-2：三处 `endswith` 统一为段边界辅助（一致性加固，低优先）

### 现状复现

Spec 4 备忘的例（`sessionpack.data_cli` 撞 `cli` 后缀）实测**不会**漏报
（探针 D2/N2c：`".cli"` 与 `"_cli"` 不同，段边界天然成立）；真正满足
`owner.endswith("." + source_module)` 的同名子包场景（探针 N2a：
`from sessionpack.foo.cli import _priv` 于 `cli/read_cmds.py`）
由 from-import 分支先行报告，route D 的过度豁免被上游覆盖，
**无独立可复现漏报**。

### 方案与取舍

- 纳入理由：route D 的豁免当前依赖"上游路线恰好也查同一名字"这一
  隐含耦合，未来路线调整（如 from-import 分支再加豁免）会静默打开
  真漏报。属防御性一致性加固，改动小、风险低。
- 做法：新增 `_owner_in_package(owner, pkg)` / 复用按段比较
  （`owner == pkg or owner.startswith(pkg + ".")` 思路），把
  import 别名分支、from-import 分支、route D 三处
  `endswith("." + source_module)` 统一替换为按段边界判定；语义等价
  或更严，不放宽任何现有放行。
- 若实施中发现某处替换改变全仓实跑结果（应无），停下复审而非改基线。

### 验收

- 新增测试 ≥1：route D 独立的同名子包豁免反例（构造一个仅 route D
  可见、from-import 分支不报的私有导入形态；若确认构造不出，
  以等价类说明 + 现有 `test_name_collision_*` 加注释收口）。
- 全仓 `check_tree` 实跑结果与改前逐字节一致（0 违规）。
