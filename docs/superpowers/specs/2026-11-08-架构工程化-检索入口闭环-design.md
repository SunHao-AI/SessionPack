# Spec 10：架构工程化——检索入口闭环

- 日期：2026-11-08
- 状态：草案（待批准）
- 前置：Spec 9（并发与竞态加固）已闭环，281 passed，已推送
- 来源：立项盘点确认的缺口——`catalog.search_messages` 消息级检索能力
  早已存在且被 Spec 8 e2e 锁死行为，但**没有任何真实入口**能触达它
  （CLI 无子命令、HTTP 无端点、Web 搜索框只走会话级过滤，
  e2e 靠测试进程内直调函数验证）。

## 1. 背景与问题

检索的"最后一公里"缺失。逐字对现场（2026-11-08）：

| 层 | 现状 | 缺口 |
|----|------|------|
| catalog | `search_messages(conn, term, limit=50)`：≥3 字走 FTS MATCH（`_fts_expr` 短语包裹），`OperationalError` 降级 LIKE，<3 字 LIKE，空串返 `[]` | 能力完整，无入口 |
| CLI | `parser.py` 仅 9 个子命令（doctor/scan/import/serve/export/verify/push/pull/rebuild），`cli/__init__.py` 登记 `_cmd_*` 9 个 | 无 `search` |
| server | `_api` 路由：`/api/sessions`（q 走 `list_sessions` 会话级过滤）、`/api/sessions/<id>`、`/api/sessions/<id>/export`、`/api/diagnostics` | 无消息级端点 |
| Web | `index.html` 搜索框提交走 `/api/sessions?...&q=`；`session.html` 无检索入口 | 用户搜不到"哪条消息" |
| 测试 | `test_e2e_flow.py` 步骤 2/6/7/8 进程内直调 `catalog.search_messages` | 真实入口零覆盖 |

即："检索能力有、检索入口无"。本 Spec 把入口补齐并让三入口
（CLI / HTTP / Web）共用同一个已锁死的 `search_messages`，
不改其任何行为。

## 2. 目标与非目标

目标：

- **R1 CLI `search` 子命令**：`sessionpack search <term> [--limit N]
  [--data-dir D] [--json]`。文本模式逐条渲染命中（会话/消息定位 +
  正文摘要行），`--json` 输出结构化命中；索引未就绪退 2（EXIT_USAGE），
  空检索词退 2；未命中退 0（检索无果不是错误）。
- **R2 HTTP `GET /api/search?q=&limit=`**：走既有 token 与回环守卫，
  返回 `{"query","count","hits":[{"session_id","message_id","body"}]}`；
  缺 `q` 退 400；limit 非法回退默认 50。
- **R3 Web 接线**：首页关键词非空时并列展示"会话列表 + 消息命中"
  （命中项链到所属会话详情页）；会话详情页加"在全部消息中检索"入口
  跳回首页自动检索；首页从 URL `?q=` 回填搜索框并自动执行。
- **R4 测试**：三入口各有一条走**真实入口**的检索环测试；
  全部新增，不触碰 `test_e2e_flow.py` 既有直调断言。

非目标：

- 不改 `search_messages` / `list_sessions` 的任何行为与签名
  （被 e2e 既有断言锁死）。
- 不做搜索结果排序/打分/高亮/分页——命中即按现有 SQL 顺序渲染。
- 不给 search 加 `--project` / 日期过滤（`list_sessions` 的会话级
  过滤已覆盖该需求，避免第二套过滤 SQL）。
- 不动 `serve` 的启动流程与 token 机制。

## 4. 设计

### 4.1 R1：CLI search

**parser.py**（读命令组内新增）：

```python
srch = sub.add_parser("search", help="全文检索消息正文（≥3 字走 FTS，其余 LIKE）")
srch.add_argument("term", help="检索词")
srch.add_argument("--limit", type=int, default=50)
srch.add_argument("--data-dir", default=None)
srch.add_argument("--json", action="store_true")
```

**read_cmds.py** 新增 `run_search` / `cmd_search`（模板沿 `run_scan`）：

- 前置：`lay = layout(args)`；`require_catalog(lay.catalog)` 为假 →
  `EXIT_USAGE` + "索引不存在，请先运行 sessionpack import"（沿 `cmd_serve`
  文案）；`args.term.strip()` 为空 → `EXIT_USAGE` + "检索词不能为空"。
- 连接：`conn = catalog.connect(lay.catalog)`，`try/finally` 关闭
  （与 e2e 同法；catalog 门面已导出 `connect`）。
- `rows = catalog.search_messages(conn, args.term, limit=args.limit)`。
- JSON 分支 `data`：`{"term", "limit", "count", "hits":
  [{"session_id","message_id","body"}…]}`（body 全量，供机读）。
- 文本分支：每命中一行
  `{session_id} #{message_id}  {摘要}`，摘要取 body 首行压缩空白后
  截 80 字符；命中数 >0 时首行 `命中 N 条（检索词"…"）`，
  未命中输出 `未命中任何消息（检索词"…"）`，退 0。

**cli/\_\_init\_\_.py**：import `cmd_search` 并登记
`_cmd_search = cmd_search`（`main` 的 `globals()` 分发即可命中）。
`__all__` 不含 `cmd_*`，无需动。

### 4.2 R2：HTTP /api/search

`server.py` `_api` 内、`/api/sessions` 分支之后插入：

```python
if path == "/api/search":
    term = (query.get("q") or [""])[0].strip()
    if not term:
        self._json(HTTPStatus.BAD_REQUEST, {"error": "缺少 q"})
        return
    try:
        limit = int((query.get("limit") or ["50"])[0])
    except ValueError:
        limit = 50
    limit = max(1, min(limit, 500))
    rows = catalog.search_messages(conn, term, limit=limit)
    self._json(HTTPStatus.OK, {"query": term, "count": len(rows),
                               "hits": [dict(r) for r in rows]})
    return
```

守卫（token/回环）在 `do_GET` 已统一把关，本分支不重复；
连接沿用 `_api` 头部既开的 `conn`（每请求一开一闭，现状不变）。

### 4.3 R3：Web 接线（app.js / index.html / session.html）

- **app.js `initIndex`**：
  - 初始化时读 `params.get("q")` 回填 `#q`，非空则自动执行一次检索；
  - `load()` 中 q 非空时并行请求 `/api/search?q=…&limit=50`；
  - 命中区渲染在会话列表上方：`<section id="hits">` 列表项 =
    会话链接（`/session?id=…`，带 token）+ `#message_id` + 正文摘要
    （首行压缩空白截 120 字符）；q 为空或无命中时清空并隐藏该区；
  - 状态行改为 `共 S 个会话 · 命中 M 条消息`（q 为空时维持原文案）。
- **index.html**：搜索表单与 `#status` 之间加
  `<section id="hits" hidden><h2>消息命中</h2><ul id="hit_list"></ul></section>`。
- **session.html**：`#actions` 内加一个"检索全部消息"表单
  （`<input id="sq">` + 提交按钮）；app.js `initSession` 提交时跳
  `/?q=<encodeURIComponent(值)>`（`link()` 自动带 token）。

纯前端拼接全部走 `textContent` / `createElement`，不引入 innerHTML，
与现有代码一致（无 XSS 面扩大）。

### 4.4 R4：测试（tests/test_search_entry.py，+8）

夹具复用 `tests/conftest.py` 的 `memory_tree` 与 `SID_A/SID_B`；
子进程模板复用 Spec 8/9 手法（`cwd` 仓库根、UTF-8 双保险）。
`test_e2e_flow.py` 一字不动。

| 用例 | 层 | 断言要点 |
|------|----|----------|
| run_search 命中 | 进程内 | import 后 `run_search`："校验" → exit 0、`data["hits"]` 的 (session_id, message_id) 序列 == e2e 步骤 2 的 `[(SID_A,"m2")]`；文本行含定位前缀 |
| run_search 边界 | 进程内 | 空词/纯空白 → EXIT_USAGE；索引不存在 → EXIT_USAGE + "索引不存在"；未命中词 → exit 0、count 0、文本"未命中" |
| run_search --limit | 进程内 | limit=0 或负数收敛为默认行为（CLI 侧夹取 `max(1, min(limit, 500))`，与 API 同规则），hits 长度 ≤ limit |
| 子进程 search --json | 子进程 | `python -m sessionpack search 校验 --data-dir … --json`：退 0、stdout 纯 JSON、hits 精确；未命中词退 0 |
| 子进程 search 缺索引 | 子进程 | 空数据目录：退 2、stderr 含"索引不存在"、stdout 无 JSON（emit 契约） |
| API /api/search | 线程内 server | 带 token "校验" → 200 且 hits 精确；缺 q → 400；无 token → 403；limit=1 生效 |
| API 与 CLI 一致性 | 线程内 + 进程内 | 同一库同一词：`/api/search` hits == `run_search` data hits（同一函数同一结果） |
| Web 静态契约 | 静态读文件 | `index.html` 含 `id="hits"` 区、`app.js` 含 `/api/search` 调用与 `params.get("q")` 回填、`session.html` 含跳首页检索表单——入口接线的存在性锁（不起浏览器） |

运行时长预算：+8 条合计 < 30s（仅 2 条起子进程、1 条起线程 server）。

## 5. 风险与决策

1. **不改 search_messages**：三入口全是薄壳；行为回归已由 e2e 既有
   断言覆盖，新增测试只锁"入口→函数"的连通与渲染契约。
2. **limit 夹取规则**（1..500）在 CLI 与 API 各写一处：两处同规则
   常量各自内联，不为两个 `min/max` 造第三模块（三行重复优于过早抽象）。
3. **正文全量入 JSON**：单条 body 可达数 KB，50 条上限下 ≤ 数百 KB，
   本地单机场景可接受；截断只发生在**文本/前端展示层**，数据层不丢信息。
4. **Web 命中区不做跳转高亮**：详情页不接 `#message_id` 锚点，
   避免动 `session.html` 渲染逻辑；命中项已带 message_id 供人工定位。
