# Spec 1：本地工程化护栏（ruff + mypy + .venv + check.py）

日期：2026-11-06
状态：已获用户逐节批准
所属系列：架构工程化 4 份 spec 之 1（护栏 → 模块边界 → 配置/错误 → 文档）

## 背景与目标

SessionPack 当前无任何静态检查护栏：无 ruff/mypy、无项目内虚拟环境（依赖 Anaconda base）、
无一键检查入口。本 spec 建立最小的本地护栏，使后续 Spec 2（模块边界重构）在
"改完跑一遍就能确认没改坏"的安全网内进行。

约束（用户决策，不可妥协）：

- 对外契约硬锁：manifest format_version=1、config.toml 格式、CLI 命令参数、HTTP 端点均不变。
- 只建本地护栏，不写 CI（GitHub Actions 明确排除）。
- 工具装到项目内 `.venv`，不污染 Anaconda base。
- mypy 宽基线起步：以现有注解能通过为准，只保证不引入新错误。
- 零第三方运行时依赖不变（ruff/mypy 仅 dev 依赖）。

## 第 1 节：方案选型（方案甲，已批准）

配置进现有 `pyproject.toml`（唯一配置源），新增 `scripts/check.py` 一键入口：

- `[tool.ruff]` / `[tool.ruff.lint]` / `[tool.mypy]` 三节写入 pyproject.toml。
- `[project.optional-dependencies] dev` 追加 `ruff>=0.6`、`mypy>=1.8`（保留现有 `pytest>=8`）。
- `scripts/check.py`（约 40 行，纯标准库）定位 `.venv` 内解释器，用其 `-m ruff` /
  `-m mypy` / `-m pytest` 依次执行。任意解释器可运行 `python scripts/check.py`，
  不要求激活 venv、不碰 Anaconda base。

否决项记录：
- 方案乙（纯配置 + README 写命令）：护栏依赖手工敲命令，会形同虚设。
- 方案丙（pre-commit 钩子）：双设备场景每台机器需 `pre-commit install`，不符轻量取向。

附带取舍（已批准）：
- 只开 `ruff check`，**不开 `ruff format`**——避免 19+13+46 行重排噪音埋掉 Spec 2 的真实 diff。
- `line-length = 100`（现存 sessionpack 最长 115，仅少数行需处理）。
- `spike/` 排除在 lint 范围外（压测报告引用的历史复现脚本，非交付代码）。

## 第 2 节：规则档位与 mypy 基线（已批准）

### ruff 配置

```toml
[tool.ruff]
line-length = 100
target-version = "py311"
extend-exclude = ["spike"]

[tool.ruff.lint]
select = ["E4", "E7", "E9", "F", "B", "UP", "I"]
ignore = []
```

各档位理由：

| 规则集 | 理由 |
|---|---|
| `E4/E7/E9` | pycodestyle 子集（导入位置、可读性、语法错误）；故意避开 E501 与 E1/E2/E3 空白类（属 format 职责，本次不开 format） |
| `F` | pyflakes：未用导入、未定义名等真 bug 探测，零争议 |
| `B` | bugbear：可变默认参、循环变量捕获等常见陷阱；勘察试跑无存量违例 |
| `UP` | pyupgrade：锁定 py311 基线，防止旧写法回潮；存量预计违例极少 |
| `I` | isort：保留（用户确认），一次性 `--fix` 自动重排（≤10 文件小改动），且让 Spec 2 拆模块后的导入整理自动归位 |

故意不选：`SIM`（过度改写建议）、`RET`（return 风格洁癖）、`ARG`（handler 未用参数合法）——
勘察试跑有十几条主观口味告警，会埋掉真信号。后续想收紧随时可加。

存量处理策略：先跑 `ruff check --statistics`；I/UP 类用 `--fix` 自动修；
不可自动修的若 ≤5 处逐个人工修；**禁止用 `# noqa` 批量压噪音**。预计人工修 ≤10 行。

### mypy 配置

```toml
[tool.mypy]
python_version = "3.11"
files = ["sessionpack"]
ignore_missing_imports = true
```

- 范围只 `sessionpack`（tests/scripts 不做类型检查——测试用 tmp_path 动态结构多，收益低）。
- 不开 `strict`、不开 `disallow_untyped_defs`（宽基线决策）。
- 基线处理：优先补一行注解；无法补的（第三方动态属性等）在**模块头部**加
  `# mypy: ignore-errors` 整体豁免并写明原因，不允许行内 `type: ignore` 满天飞。
- 目标：首跑退出码 0。

### scripts/check.py 行为契约

1. 定位解释器：`<仓库根>/.venv/Scripts/python.exe`（Windows）或 `bin/python`（POSIX）；
   不存在则打印 venv 创建指引并退出码 2。
2. 依次跑 `ruff check .` → `mypy` → `pytest -q`；任一失败立即停止并以该步退出码退出
   （fail-fast，输出直接透传不吞）。
3. 任意解释器可执行：`python scripts/check.py`，不要求激活 venv。
4. 支持 `python scripts/check.py --only ruff|mypy|pytest` 单跑一步。

## 第 3 节：改动清单与验收（已批准）

### 验收标准

1. 新终端 `python scripts/check.py` 退出码 0（ruff 0 违例 → mypy 0 错误 → pytest 144 passed）。
2. `python scripts/check.py --only mypy` 单步可用。
3. 删除 `.venv` 后运行 `check.py` 打印创建指引并以退出码 2 结束（不裸报错）。
4. `git status` 干净（`.venv/`、`.ruff_cache/` 已被现有 .gitignore 覆盖，无需改 .gitignore）。
5. 全量测试数与开始前一致（144 passed），证明零行为变更。

### 实现顺序（writing-plans 骨架）

1. 建 `.venv` 并 `pip install -e .[dev]`
2. 落 pyproject 三节配置
3. 写 `scripts/check.py`
4. 首跑 `ruff check` 清存量（--fix + 人工）
5. 首跑 `mypy` 清基线
6. 全量 `check.py` 绿
7. README 补开发环境小节
8. commit
