## B. Follow-up 技术项（终审裁定"不立项、记录在案"，可各自单独开对话）

### B1. 口令不符信封静默重推导致同步目录膨胀（T4②，建议优先）

- **描述**：push 判重时，口令不同的既有信封解不开 → `have_ids` 不可见 → 每次 push 都静默重推一份新信封，目录无限膨胀且报告零提示。
- **背景**：`sessionpack/sync.py` `push_archives` 加密分支按解密后 manifest 的 archive_id 判重；AAD 绑定信封文件名，换口令即 GCM 失败（E202），按"不可见"处理是有意取态，但缺用户侧信号。
- **要求**：给 CLI push 报告增加"无法解密的信封数"（文本 + `--json` payload 字段），不改变"重推一份"的既有行为本身；补回归测试。

### B2. PBKDF2 全量判重/幂等的性能墙（T4④ + T5③ 合并项）

- **描述**：push 判重与 pull 幂等对目录下**全部**信封逐个做全量 PBKDF2（600k 迭代，约 0.4s/个）；信封数破百后 push/pull 线性变慢。
- **背景**：D5 规定内容无关随机命名，判重必须解密读 manifest，属架构固有代价。
- **要求**：候选方案任选其一并评测——每进程缓存派生 key（同口令只派生一次）、首包试解探测后再批量、本机已导入信封名清单持久化。需带性能对比测试或基准说明。

### B3. 两个 lint 测试文件合并（T2②）

- **描述**：`tests/test_script_lint_imports.py` 与 `tests/test_lint_imports.py` 并存，导入/调用风格两套。
- **背景**：`test_script_lint_imports.py` 是 plan 指定文件名；两文件都测 `scripts/lint_imports.py` 的规则。
- **要求**：合并为一个文件、统一为一种调用风格（`check_source(src: str, rel: str, warnings=None)`），不减少任何既有用例。

### B4. config `[sync].encrypt` 非 dict 镜像用例（T3①）

- **描述**：`test_sync_encrypt` 系列缺"encrypt 段整体非 dict"（如 `encrypt = 1` 出现在 `[sync]` 下值为非 bool、或结构整体畸形）的镜像用例。
- **背景**：config 层取态是"非 True 一律 False、不抛错"（G4），读取用 `value is True`；既有测试只覆盖了缺键与正常 bool。
- **要求**：补参数化用例锁死"任何非 True 形状 → sync_encrypt 返回 False 且不抛"。

### B5. pull 文案逐项断言 + 文本模式机器可读信号（T6-2）

- **描述**：CLI pull 的口令失败/信封跳过文案未逐项断言；文本模式无机器可读的 invalid 信号（`--json` 有 `skipped_invalid`，文本模式只能靠肉眼）。
- **要求**：对 pull/purge 关键文案做逐项断言；评估文本模式是否需要输出 invalid 计数行（先小步，不扩 CLI 语义）。

### B6. reencrypt 文案前缀风格与 push 分叉（T8-3）

- **描述**：`run_reencrypt` 的输出行前缀风格（"已转换/跳过:/转换失败:"）与 push/pull 既有文案风格不一致。
- **要求**：统一为项目既有文案风格（先 grep push/pull 现行前缀定基准），同步更新受影响测试断言。

### B7. reencrypt `--json` payload 断言（T8-5）

- **描述**：Task 8 的 4 个测试只走目录状态断言，未断言 `--json` 输出 payload（`converted/skipped/errors/sync_dir` 四键）。
- **要求**：补一条 JSON 模式断言用例（注意既有注释"`_run_cli` 的 json 渲染不进 capsys 返回值断言路径"，需找正确的捕获方式或直调 `run_reencrypt`）。

### B8. unlink 失败测试补 `converted == 0` 显式断言（复审 M-3）

- **描述**：`tests/test_cli_commands.py` 中"原包删除失败"回归测试（Path.unlink 打桩）只断言 exit_code/errors，`converted==0` 仅被逻辑蕴含。
- **要求**：补一行 `assert res.data["converted"] == 0`。一行改动，可搭 B7 顺带。

### B9. `_scan_sync_candidates` 候选集未收敛到 `is_envelope_name`（复审 M-4）

- **描述**：`sync.py` `_scan_sync_candidates` 仍收任意非点号 `*.spk` 进候选；非规范名 `.spk` 走 zip 分支 → verify 失败 → `skipped_invalid`，行为安全但多一条噪声跳过记录。
- **背景**：终审已裁定行为安全、不扩修复波范围；信封名判定已单源化到 `crypto.is_envelope_name`（宽松：前缀 `spk-` + 后缀 `.spk`）。
- **要求**：若处理，需在 spec 说明"杂散 .spk 静默忽略 vs 记 invalid"的取态变更；不处理则维持现状。
