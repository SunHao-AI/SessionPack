# SessionPack 使用说明（本地只读）

## 数据路径

- 记忆目录（只读）：`%USERPROFILE%\.trae-cn\memory`
- 索引与归档目录：`%LOCALAPPDATA%\SessionPack`
  - `catalog.sqlite`：可重建的索引
  - `archives/`：归档包默认输出目录（由 `export --archive --out` 指定时以 `--out` 为准）
  - `temp/`：预留的临时目录；打包实际在输出目录内用 `.build-*` 子目录与 `.tmp-*.zip` 临时文件完成，失败后可整体删除
- 可用 `--data-dir` 覆盖索引目录，`--memory-root` 覆盖记忆目录。

## 隐私边界

- 只打开白名单文件：`topics.md`、`session_memory_*.jsonl`、各项目 `project_memory.md`、根 `user_profile.md`。
- 同目录的 `trae-jwt-token` 与账号标识目录不会被打开。`import --audit` 会记录本次实际打开的文件，并在导入结束时统一判定，越界即失败退出（事后审计）。
- 私有库 `%APPDATA%\Trae CN\ModularData\ai-agent\database.db` 为加密格式，工具只报告其路径与体积，不解析、不复制。
- `doctor`、日志与导出内容不含 token；导出文件包含会话正文，分享前请自行确认范围。

## 兼容性

- Python 3.11 及以上。自 Spec 14 起，唯一运行时第三方依赖是 `cryptography`（仅同步加密使用）；其余功能仍只用标准库。全程不联网，不传任何数据。
- FTS5 需要 SQLite 3.34+ 且提供 trigram 分词器；检索词少于 3 字或 FTS 查询报错时自动退回 LIKE 检索，实际分词器可由 `doctor --json` 的 `catalog.tokenizer` 查看。
- 适配器以 Trae CN 3.4.14 验证；其他版本按实验性支持，字段缺失或不可解析时跳过该行并计入失败行。
- 归档格式 `format_version = 1`，读取方必须忽略不认识的字段；破坏性变更才递增版本号。

## 哪些历史搜不到（记忆能力覆盖边界）

索引只覆盖记忆目录中出现过的内容，三类情况按覆盖程度递减：

1. **有记忆条目**：项目内存在 `session_memory_*.jsonl`，逐轮记录可全文检索。
2. **只有摘要**：只在 `topics.md` 有条目而无 jsonl 文件，检索得到摘要行、检索不到会话正文（如 `actions`/`learned` 等未落 jsonl 的字段搜不到）。
3. **都没有**：既无 jsonl 也无 topics.md 条目，完全不在覆盖范围内（关闭记忆能力的会话属于此类）。

本机最小口径扫描结果（`python scripts/memory_coverage_scan.py`，2026-11-06，样本范围=单机单用户）：

```text
-d-Workplace-ChageeCupDrawing--p2-faebe1904e30bc2d221d	有记忆条目	记忆条目=2	摘要条目=7
-d-Workplace-cv-utils--p2-b84bc357b0cab5d65a68	有记忆条目	记忆条目=1	摘要条目=1
-d-Workplace-FastAPI-Hao	有记忆条目	记忆条目=1	摘要条目=0
-d-Workplace-flysee-video-setting--p2-6def0c0327a7fabf9072	有记忆条目	记忆条目=2	摘要条目=2
-d-Workplace-modelctl--p2-feb5fcf95c0a55f143c8	只有摘要	记忆条目=0	摘要条目=1

```

读法：7 个项目中 6 个有记忆条目（共 10 个唯一会话），1 个（modelctl）只有摘要、没有 jsonl，因此该项目的会话正文完全搜不到；0 个项目完全缺失。

完整口径（开启/未开启记忆能力的会话对照）依赖跨版本样本积累，随 B2 复验时补充。

## 对 IDE 的影响

- 工具只读取记忆目录中的文本文件，不打开、不锁定 Trae 的私有数据库和 WAL。
- 读取发生在导入瞬间，按行流式处理，不会持续占用文件句柄。
- 导入过程中 Trae 可以继续使用；新写入的记忆文件会在下次 `import` 时按大小与修改时间增量更新。

## 跨设备同步

用你自己控制的目录（网盘/NAS 挂载盘、U 盘目录都行）在两台设备间搬运归档包：

```text
# 设备 A：推送本地归档包到同步目录（首次用 --dir，之后可省略）
sessionpack push --dir D:\Sync\sessionpack                # 首次指定同步目录（落盘 config.toml）
sessionpack push                                          # 之后免参数（沿用已落盘的同步目录）
sessionpack push --dir D:\Sync\sessionpack --encrypt      # 加密推送：只落 spk-*.spk 信封
sessionpack push --dry-run          # 只看将推什么，不写入

# 设备 B：拉取并自动导入索引（目录里有 *.spk 才要口令，明文包照旧免口令）
sessionpack pull --dir D:\Sync\sessionpack

# 存量明文同步目录一次性转加密（fail-safe：自检通过才删原包）
sessionpack reencrypt --dir D:\Sync\sessionpack
```

推送落盘的配置形如：

```toml
[sync]
dir = 'D:\Sync\sessionpack'   # push --dir 之后才有这行
encrypt = true                # push --encrypt 之后才有这行（缺省 = 明文推送）
```

> `push` 的 `--dir` 会在成功推送后写入配置供后续省略；`pull` 的 `--dir` 只对本次生效，不落配置（`pull` 不读写该配置，两台设备可各自指定不同同步目录）。

- **只增不删**：push/pull 都只往对方缺的地方补包，永不删除任何一端的既有文件；规范命名包（`*-<archive_id前12位>.zip`）同名或同 `archive_id` 时跳过、永不覆盖，其余文件也不会被触碰。
- **幂等**：重复执行不会产生重复包或重复消息（同名跳过、同 `archive_id` 去重、导入层本身幂等）。
- **坏包隔离**：推送前逐包校验，拉取时先校验后导入，坏包只记入报告不扩散。

> **提醒：默认推送的归档包是明文 zip**（含会话标题、摘要、消息文本）。放入网盘/NAS 前请确认该目录的访问范围符合你的隐私预期。

> 开启 `--encrypt` 后同步目录只出现 `spk-<32位hex>.spk` 随机名信封——项目名、日期、包 id、会话内容在云侧全部不可见；口令经环境变量 `SESSIONPACK_PASSPHRASE` 或交互输入（两次一致），**不落盘**；换机/新设备 pull 时输入同一口令即可。
>
> **警告（忘口令不可恢复）**：口令只在你输入时存在于内存，工具不保存、无法找回；忘记口令后同步目录中的信封等同乱码，只能重推。
>
> 存量明文目录用 `sessionpack reencrypt` 一次性转换（转换后立即删除原明文 zip；加密开关会随 `push --encrypt` 持久化到 `config.toml` 的 `[sync].encrypt`）。加密格式见 [同步加密设计](superpowers/specs/2026-11-09-同步加密-design.md)。

## 删除与撤销

    sessionpack delete --session ID           # 软删除（墓碑）
    sessionpack delete --session ID --undo    # 撤销（仅本机）

- **删除 = 隐藏 + 不复活，不是抹除**：墓碑只把会话从列表、详情、检索与项目计数
  中隐藏，消息行与归档文件都保留。同步目录中的历史包仍含全文；需要真抹除见下文
  《物理清除（不可逆）》。
- **删除经归档包传播**：删除后 `export --archive` 生成的包带墓碑标记，push 到同步
  目录、他机 pull 后该会话同样隐藏。全新设备直接导入墓碑包也有效。
- **墓碑优先**：一旦某设备落下墓碑，再导入删除之前生成的旧归档包也不会复活该会话。
- **撤销只在本机**：`--undo` 只恢复本机视图，不跨设备传播——他机若已导入墓碑包，
  需在那台设备上各自执行 `delete --undo`。这是"墓碑优先"的必然代价。

#### 物理清除（不可逆）

```
sessionpack delete --session ID --purge --yes
sessionpack delete --session ID --purge --yes --dir D:\Sync\sessionpack  # 同步目录缺省读配置，--dir 仅本次生效
```

仅对已软删除的会话生效（active 需先 delete）。执行三件事：本机索引抹除该会话
全部消息与主题（sessions 行保留为 `purged` 终态卡，不再展示任何内容）；本机
归档目录中含该会话内容的包原位重打包（正文替换为空、meta 换成 purged 卡，
archive_id 随之变化 = 本机改名）；同步目录只扫描报告、不改动。此后任何 import、
旧包 install、rebuild 都不会让该会话复活。

> **警示**：若清除报告出现"重打包失败"（`archives_failed` 非空），在修复并重跑
> 清除之前，勿执行 `rebuild --from-archives`——purge 卡只随带卡的包存在，重放
> 失败留在场内的旧包（仍含该会话内容）可能把终态卡洗掉。
